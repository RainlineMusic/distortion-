# 0.1.1 — исчезновение показаний

Пользовательский сценарий: Ableton, VST3, 48 кГц, буфер 1024. Число появлялось после накопления данных и сразу исчезало.

Исправлены подтверждённые по коду причины повторного накопления:

- Один тихий блок (21.33 мс при этих настройках) больше не сбрасывает всю историю. В очередь записываются реальные нулевые сэмплы. Непрерывная тишина 250 мс убирает показание.
- Расхождение позиции транспорта в пределах двух сэмплов не считается seek. Повторяющиеся timestamps не считаются перемоткой; прогноз sample count продолжает двигаться. Настоящий seek и play/stop по-прежнему очищают показание.
- При временных статусах Measuring / Insufficient можно видеть последнее достоверное число той же эпохи максимум 2 секунды. Удержание не продлевает срок давности. При отключении sidechain, неверных сэмплах, несвязанном сигнале и переполнении оно не применяется.

Математика и пороги достоверности оценки не ослаблены ради постоянного отображения числа. Формулы THD и остатка не изменены.

Регрессии: 48 кГц / 1024, повторяющиеся короткие тихие блоки, непрерывность при округлении и повторении timestamp, сброс при настоящих перемотках и остановке, ограниченный срок удержания, отсутствие выделений new/new[] на потоке захвата. Это симуляция указанного режима; приложение Ableton в локальной среде не запускалось.

Локальная проверка исправления: CTest DSP / Realtime / HarmonicCalibration — 3/3; 51 сравнение процентных результатов и отрицательные проверки — без ошибок. В Release-тесте с короткими паузами число было доступно в 91 из 99 опросов после прогрева. ASan/UBSan для realtime-регрессий — без ошибок (локально detect_leaks=0 по ограничению среды). Изменённый JUCE PluginProcessor.cpp успешно скомпилирован. Платформенные сборки и native integration выполняет GitHub Actions.
