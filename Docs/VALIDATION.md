# Протокол проверки — 29 октября 2026

Среда: Linux x86_64, GCC 13.3.0, CMake 3.28.3, JUCE 8.0.4, Release. Эти результаты не заменяют проверку конкретного Windows/macOS-хоста.

## Известные гармоники

Независимый Python-генератор создаёт float32 WAV 48 кГц: чистый PRE 997.3 Гц, POST с H2 = 0.6D и H3 = 0.8D относительно основной. Gain POST уменьшен вдвое. По определению `sqrt((0.6D)^2 + (0.8D)^2) = D`. Измерены три окна каждого файла.

| Задано | Фактический диапазон измерений | Максимальная абсолютная ошибка |
| ---: | ---: | ---: |
| 0% | 0.000000068–0.000000085% | 8.55e-08 п.п. |
| 0.1% | 0.099999989–0.100000019% | 1.89e-08 п.п. |
| 1% | 0.999999987–1.000000024% | 2.39e-08 п.п. |
| 5% | 4.999999999–5.000000003% | 3.05e-09 п.п. |
| 10% | 9.999999984–10.000000009% | 1.55e-08 п.п. |

Это точность на этих контролируемых сигналах, не универсальная гарантия на музыке. WAV и JSON находятся в `Examples/Calibration`; скрипт — `Tools/calibrate.py`. Дополнительные C++ калибровки проверяют 44.1, 48, 96 и 192 кГц, уровни 0/0.1/1/5/10%, комбинацию H2=3% + H3=4%, полярность и частоты вне FFT-бинов, включая 31.17 Гц.

В самом JUCE-процессоре POST подан на main input, PRE — на настоящий auxiliary bus. Результат 3% H2 + 4% H3: **5.00%**. Скриншот `Docs/Previews/thd-5-percent.png` получен из этого измерения. `residual-example.png` — отдельно обозначенный синтетический пример интерфейса.

## Линейные цепочки и нелинейный остаток

Всего 51 сравнение процентного результата плюс отрицательные проверки. Примеры из финального подробного протокола:

| Проверка, 48 кГц | Результат |
| --- | ---: |
| Identical | 0.000000515% |
| FIR EQ | 0.000000497% |
| IIR low-pass с полюсом 0.99 | 0.000019631% |
| Gain ±6/12 dB, полярность, DC | проходит null-порог теста |
| Задержка 1, 173, 5000, −817 сэмплов | найдена точно; проходит null-порог |
| Fractional delay 32.37 сэмпла | проходит null-порог |
| All-pass и стереоматрица с crossfeed | проходят null-порог |

На независимом широкополосном шуме добавленная некоррелированная составляющая с RMS-отношением 1% дала около 1.039% относительно выхода. Hermite cubic с теоретическим остатком 0.99995% дал **1.06492%**; при теоретических 4.99376% — **5.31359%**. Это показывает ненулевую погрешность конечной BLA/FIR-оценки. Данные не подгоняются для искусственного совпадения с теорией. Проверка на музыке не сертифицирует точную долю новых гармоник.

Hard clipper на синусе показывает последовательный рост при понижении порога. Тишина, отсутствующий reference, NaN, разные длины, несвязанный материал и недостаточное спектральное возбуждение не дают фиктивного процента. Короткий периодический широкополосный шаблон отклоняется, чтобы FIR не мог запомнить его нелинейный выход как линейную характеристику.

## Поток, процессор и форматы

- **CTest: 5/5** групп — DSP, Realtime, HarmonicCalibration, CLAPSmoke, Integration. Полный подробный вывод: `Docs/Checks/ctest-full.txt`.
- Проверены 336 сочетаний частоты, main/sidechain layout, float/double и размера блока (1, 7, 32, 64, 127, 512, 2048). Проверяется битовое равенство main и auxiliary samples до/после processBlock, а также host bypass.
- Тест SPSC покрывает переполнение, wraparound и конкурентную передачу 10000 сообщений. Перехват new/new[] на потоке захвата: **0 выделений**. Проверены сброс эпохи и отсутствие устаревшего числа после invalidate. Финальный повтор после уточнения атомарной публикации — `Docs/Checks/ctest-final-realtime.txt`.
- **ASan + UBSan: 3/3**, затем отдельный финальный Realtime — успешно. `ASAN_OPTIONS=detect_leaks=0:halt_on_error=1`, `UBSAN_OPTIONS=halt_on_error=1`. LeakSanitizer здесь не проверен: среда запрещает доступ к task-данным /proc, который ему нужен. В CI address-job запускается без этого локального отключения leak-check.
- **VST3: pluginval 1.0.4, strictness level 5 — SUCCESS.** Проверены открытие окна, float/double processing, state и доступные шины. Протокол: `Docs/Checks/pluginval-linux.txt`. Для доступного X-сервера в этой среде использовалось TCP-подключение к локальному Xvfb; обычный UNIX display здесь недоступен.
- **CLAP:** динамическая загрузка готового модуля через CLAP API, factory/instance initialization, два стереовхода (main/reference), один стереовыход, побитовое совпадение основного float-сигнала. Это smoke-test собственного маленького хоста, не полная CLAP conformance suite.
- Нативные 2× UI-captures просмотрены; отдельное ревью интерфейса: **ship**, без обязательных исправлений. Accessibility descriptions проверены в коде; screen reader не проверялся.
- **Workflow: actionlint 1.7.7 — exit 0.** Сборки Windows x64 и macOS Universal, их pluginval и AU validation подготовлены в Actions; они выполнятся после загрузки пользователем исходников в репозиторий. Они не объявляются уже пройденными.

## Границы проверки

Не проведены измерения на конкретных коммерческих EQ/компрессорах/лимитерах, проверка в пользовательской DAW, непрерывный sample-clock drift, PACE-подписанный AAX и сертифицированная метрологическая оценка. Конечная FIR не гарантирует точной компенсации любого линейного тракта. Fast offline render может переполнить очередь: аудио не блокируется, число убирается; для такого сценария предоставлен синхронный WAV CLI.
