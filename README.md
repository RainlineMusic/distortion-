# Distortion 0.1.3

Плагин анализа с внешним sidechain. В окне 800 × 648 сверху показаны спектры **Before / After**, ниже — **Added residual**, в отдельной панели — **Short / Integrated** и **Reset**. Momentary отсутствует. Inter и Solid Dark перенесены из Clip Pocket; нет настроек, активации и кнопки bypass. Основной сигнал проходит без изменения сэмплов и без добавочной задержки.

## Подключение

1. Создай точку разветвления **перед всей обработкой мастера**, включая EQ и изменение уровня.
2. Основную ветку отправь через мастеринг-цепочку. Поставь Distortion последним.
3. Необработанную ветку направь **только во внешний sidechain** `Reference (Pre)` у Distortion. Не подмешивай её в слышимый выход. Уровень посыла — постоянный; никакого feedback обратно в мастер.
4. Включи внешний sidechain в хосте и проиграй непрерывный фрагмент. Дождись обучения линейной модели. После него Integrated начинает накапливаться, а Short появляется после трёх секунд пригодных сэмплов; значения обновляются каждые 100 мс. Время обучения зависит от материала и расчёта.

Если DAW не умеет посыл с мастера до insert-эффектов, сделай отдельную шину **Pre Master**. Направь все дорожки в неё, а из неё сделай две ветки: мастер с обработкой и sidechain анализатора. Вторая ветка не должна звучать отдельно. Выводить два экземпляра плагина PRE/POST не требуется.

Прочерк означает, что для данного показания ещё нет пригодных данных. При отсутствии спектра окно подсказывает подключить необработанный сигнал к sidechain; до получения модели показывает `Learning the linear response...`. На паузе Short становится недоступен. Пауза и смена эпохи захвата сохраняют накопленный Integrated; Short при новой эпохе набирается заново. Reset очищает только Integrated и измеренное время, сохраняя Short. Перезапуск анализатора при новой конфигурации начинает новый замер.

## Что означает процент

Оба живых показания — **оценка остатка**, `100 × sqrt(Σ e² / Σ yAC²)`, где `e = y − ŷlinear`. Знаменатель использует POST без среднего каждого 100-мс блока; энергии каналов суммируются. Short охватывает три секунды пригодных сэмплов. Integrated суммирует энергии с момента сброса, а не усредняет проценты; обучение и недоступные данные в него не входят.

Линейная модель учитывает постоянные gain, полярность, задержку, конечный FIR/EQ, фазу и фиксированную стереоматрицу. Остаток включает нелинейность, шум, изменение gain компрессора и ошибки модели. Это **не истинный THD музыки или живого тестового синуса**, не точная доля «новых гармоник» и не показатель слышимости. В WAV CLI сохранён отдельный гармонический THD_F для чистого синуса; его знаменатель отличается от живого остатка.

Графики показывают сырые спектры сигнала в **dBFS / 1/6 octave**: Before зелёный, After синий, остаток янтарный. Это не передаточная функция системы. Здесь нет LUFS-взвешивания, loudness gating или заявления о сертификации. Подробности: [Docs/DSP.md](Docs/DSP.md).

## Явная проверка гармониками

В `Examples/Calibration` находятся моно WAV 48 кГц с чистым синусом 997.3 Гц и выходами с известными гармониками. Основная частота в POST ослаблена на 6.0206 dB; это проверяет независимость результата от gain.

| Файл POST | H2 / основная | H3 / основная | Ожидается |
| --- | ---: | ---: | ---: |
| `post-1-percent.wav` | 0.6% | 0.8% | 1.00% |
| `post-5-percent.wav` | 3% | 4% | 5.00% |
| `post-10-percent.wav` | 6% | 8% | 10.00% |

Точные значения из таблицы проверяются гармоническим методом WAV CLI, а не показаниями Short / Integrated. Файлы PRE/POST должны иметь общее начало и не проходить дополнительную обработку. Полная проверка 0%, 0.1%, 1%, 5%, 10% воспроизводится скриптом:

```bash
python Tools/calibrate.py --analyzer /path/to/DistortionAnalyze --output calibration
```

Независимое ожидание: `sqrt(3² + 4²) = 5%`. Генератор не вызывает DSP анализатора при создании сигналов. Фактический протокол — [Docs/VALIDATION.md](Docs/VALIDATION.md).

## Сборка через GitHub Actions

Загрузи **содержимое** архива в корень `RainlineMusic/distortion-`: файл `CMakeLists.txt` должен лежать в корне репозитория. Затем открой **Actions → Build Distortion macOS and Windows → Run workflow**. Push в `main` также запускает сборку. Workflow, загруженный раньше исходников, завершит только проверку их наличия и предложит загрузить исходники.

Артефакты: **Windows x64 VST3 / CLAP**, **macOS Universal VST3 / AU / CLAP**, а также AAX Developer и протоколы тестирования. macOS подписывается Developer ID при наличии тех же secrets, что в Clip Pocket; иначе артефакты явно помечаются `AdHoc`. Notarization не выполняется. AAX Developer не является PACE-подписанным релизом для обычного Pro Tools.

Локально на Linux проверены DSP, очередь, JUCE-процессор, интерфейс и VST3/CLAP. Windows/macOS workflow подготовлен; реальные сборки и host-проверки этих платформ выполнятся после загрузки исходников. Инструкции — [Docs/BUILD.md](Docs/BUILD.md).

Для быстрого offline bounce аудио остаётся неизменным, но очередь анализа может переполниться: тогда текущий захват становится недоступен; уже накопленный Integrated сохраняется. Для воспроизводимого офлайн-измерения экспортируй PRE/POST WAV с общей временной шкалой и используй `DistortionAnalyze`; он не нормализует, не ресемплирует и не обрезает несовпадающие файлы автоматически.
