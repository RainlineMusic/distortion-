# Distortion 0.1.0

Плагин измерения искажений с внешним sidechain. В окне только **Distortion** и процент. Inter и Solid Dark перенесены из Clip Pocket; нет настроек, активации и кнопки bypass. Основной сигнал проходит без изменения сэмплов и без добавочной задержки.

## Подключение

1. Создай точку разветвления **перед всей обработкой мастера**, включая EQ и изменение уровня.
2. Основную ветку отправь через мастеринг-цепочку. Поставь Distortion последним.
3. Необработанную ветку направь **только во внешний sidechain** `Reference (Pre)` у Distortion. Не подмешивай её в слышимый выход. Уровень посыла — постоянный; никакого feedback обратно в мастер.
4. Включи внешний sidechain в хосте и проиграй непрерывный фрагмент. Первое число обычно появляется через 2–4 секунды; дальнейший анализ выполняется примерно раз в 0.5 секунды плюс время расчёта.

Если DAW не умеет посыл с мастера до insert-эффектов, сделай отдельную шину **Pre Master**. Направь все дорожки в неё, а из неё сделай две ветки: мастер с обработкой и sidechain анализатора. Вторая ветка не должна звучать отдельно. Выводить два экземпляра плагина PRE/POST не требуется.

Прочерк означает: нет reference, тишина, идёт накопление данных, недостаточный спектр, несвязанные сигналы или потерян захват. После seek, loop, отключения sidechain и смены частоты старое значение сбрасывается. Подпись состояния доступна через accessibility; дополнительные элементы в окне не появляются.

## Что означает процент

**Чистый синус на sidechain:** автоматически измеряется гармонический **THD_F** — RMS-сумма выходных гармоник относительно выходной основной частоты. Учитываются H2…H64, ограниченные 20 кГц и частотой Найквиста. DC и негармонический шум в эту величину не входят. Постоянный gain и фаза не меняют результат. Такой режим позволяет проверить известные 1%, 5%, 10%.

**Музыкальный / широкополосный сигнал:** показывается **оценка остатка** `100 × RMS(y − ŷlinear) / RMS(yAC)`. Линейная модель компенсирует постоянные gain, полярность, задержку, конечный FIR/EQ, фазу и фиксированную стереоматрицу; DC учитывается отдельно. Модель обучается на прошлом участке, а процент вычисляется на отложенном участке. Это не универсальный THD музыки: остаток включает нелинейность, шум, изменение gain компрессора и ошибки конечной модели. Нельзя трактовать его как точную долю «новых гармоник» или показатель слышимости.

Метод определяется входным сигналом автоматически, без переключателя. Числа двух методов имеют разные знаменатели. На музыке условные 5% остатка нельзя напрямую сравнивать с 5% THD тестового синуса. Подробности: [Docs/DSP.md](Docs/DSP.md).

## Явная проверка гармониками

В `Examples/Calibration` находятся моно WAV 48 кГц с чистым синусом 997.3 Гц и выходами с известными гармониками. Основная частота в POST ослаблена на 6.0206 dB; это проверяет независимость результата от gain.

| Файл POST | H2 / основная | H3 / основная | Ожидается |
| --- | ---: | ---: | ---: |
| `post-1-percent.wav` | 0.6% | 0.8% | 1.00% |
| `post-5-percent.wav` | 3% | 4% | 5.00% |
| `post-10-percent.wav` | 6% | 8% | 10.00% |

Положи `reference-997Hz.wav` и один POST на две дорожки **с одинаковым началом и без обработки**. POST отправь на обычный вход Distortion; reference — только на его sidechain. После накопления окна ожидается соответствующий процент. Полная проверка 0%, 0.1%, 1%, 5%, 10% воспроизводится скриптом:

```bash
python Tools/calibrate.py --analyzer /path/to/DistortionAnalyze --output calibration
```

Независимое ожидание: `sqrt(3² + 4²) = 5%`. Генератор не вызывает DSP анализатора при создании сигналов. Фактический протокол — [Docs/VALIDATION.md](Docs/VALIDATION.md).

## Сборка через GitHub Actions

Загрузи **содержимое** архива в корень `RainlineMusic/distortion-`: файл `CMakeLists.txt` должен лежать в корне репозитория. Затем открой **Actions → Build Distortion macOS and Windows → Run workflow**. Push в `main` также запускает сборку. Workflow, загруженный раньше исходников, завершит только проверку их наличия и предложит загрузить исходники.

Артефакты: **Windows x64 VST3 / CLAP**, **macOS Universal VST3 / AU / CLAP**, а также AAX Developer и протоколы тестирования. macOS подписывается Developer ID при наличии тех же secrets, что в Clip Pocket; иначе артефакты явно помечаются `AdHoc`. Notarization не выполняется. AAX Developer не является PACE-подписанным релизом для обычного Pro Tools.

Локально на Linux проверены DSP, очередь, JUCE-процессор, интерфейс и VST3/CLAP. Windows/macOS workflow подготовлен; реальные сборки и host-проверки этих платформ выполнятся после загрузки исходников. Инструкции — [Docs/BUILD.md](Docs/BUILD.md).

Для быстрого offline bounce аудио остаётся неизменным, но очередь анализа может переполниться: тогда вместо устаревшего процента будет прочерк. Для воспроизводимого офлайн-измерения экспортируй PRE/POST WAV с общей временной шкалой и используй `DistortionAnalyze`; он не нормализует, не ресемплирует и не обрезает несовпадающие файлы автоматически.
